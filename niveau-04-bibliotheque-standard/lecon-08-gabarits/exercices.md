# Leçon 8 — Exercices

Code dans `mes-solutions/niveau-04/lecon-08/`.

## Exercices faciles

**E1 — L'injection, mesurée.**
Avec le gabarit `<p title="{{.}}">{{.}}</p><script>var x = {{.}};</script><a href="{{.}}">l</a>`,
exécuter **les deux paquets** sur ces quatre valeurs : `Tom & Jerry`, `"><img src=x onerror=alert(1)>`,
`javascript:alert(1)`, `</script><script>alert(1)</script>`. Présenter les 8 sorties. Pour
chaque sortie de `text/template`, dire si un navigateur exécuterait du code.

**E2 — Espaces.**
Écrire un gabarit qui produit **exactement** (vérifier avec `cat -A`) :

```
Courses :
- pain
- lait
- œufs
Total : 3 articles
```

à partir de `[]string{"pain", "lait", "œufs"}`, avec un `range` dont les balises sont sur leurs
propres lignes dans le source du gabarit. Sans `{{-`, combien de lignes vides obtient-on ?

**E3 — `<no value>`.**
Exécuter `Bonjour {{.Nom}}` sur `map[string]string{"nom": "Awa"}` avec `text/template`, puis
avec `html/template`, puis avec `Option("missingkey=error")`, puis sur une struct avec un champ
`Nom`. Quelle forme de donnée protège le mieux contre les fautes de frappe ?

**E4 — `FuncMap`.**
Ajouter les fonctions `money` (des `Cents` vers `"12,34 €"`), `plural` (`{{plural .N "article"
"articles"}}`) et `date` (`time.Time` vers `02/01/2006`). Que se passe-t-il si `Funcs` est
appelé après `Parse` ? Recopier le message.

**E5 — Sortie partielle.**
Exécuter vers `os.Stdout` un gabarit qui échoue à la troisième ligne (fonction du `FuncMap` qui
rend une erreur). Qu'est-ce qui est affiché ? Corriger avec un `bytes.Buffer`.

## Exercice intermédiaire — Générateur de rapport

Reprendre le journal d'accès de la leçon 2 et générer **deux** rapports à partir de la **même**
struct de vue :

1. `rapport.txt` avec `text/template` : tableau aligné en colonnes (`printf "%-20s"`).
2. `rapport.html` avec `html/template` : tableau HTML, une ligne rouge pour chaque statut ≥ 500.

**Contraintes :**
1. Les gabarits sont dans des fichiers `templates/rapport.txt.tmpl` et `templates/rapport.html.tmpl`,
   **embarqués** avec `//go:embed` et chargés avec `ParseFS`.
2. Une mise en page commune `base.html.tmpl` avec un `{{block "content" .}}`.
3. La struct de vue contient des valeurs **déjà calculées** (totaux, pourcentages formatés) : aucun
   calcul dans les gabarits.
4. Écriture atomique des deux fichiers (leçon 7) ; rien n'est écrit si l'un des gabarits échoue.
5. Un chemin de requête contenant `<script>` dans les données de test ne doit produire aucun
   script dans le HTML — vérifier en ouvrant le fichier dans un navigateur.

## Défi — Générer du code Go

Écrire un générateur qui lit une liste de valeurs (`low,medium,high`) et produit un fichier
`level_gen.go` contenant le type, les constantes avec `iota`, une méthode `String()` et une
fonction `ParseLevel(string) (Level, error)`.

1. Utiliser `text/template` (pourquoi pas `html/template` ici ?).
2. Passer la sortie dans `go/format.Source` : si elle ne compile pas syntaxiquement, le
   générateur échoue au lieu d'écrire un fichier cassé.
3. En tête du fichier, la ligne conventionnelle `// Code generated by … DO NOT EDIT.` — chercher
   dans `go help generate` le format exact attendu, et ce que les outils en font.
4. Ajouter dans un fichier du paquet la directive `//go:generate go run ./gen low,medium,high`
   et lancer `go generate ./...`.
